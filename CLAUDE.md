# Rupantar

Cross-platform desktop app (Tauri v2 + Rust backend; React + TypeScript + Vite + Tailwind + Framer Motion frontend). Tray-resident file-conversion utility.

**UX flow:** the user summons a circular radial menu at the cursor (hotkey or file drop), drops/selects files, flicks toward an operation wedge, and the converted file is written next to the original.

**Everything runs locally. No network access, ever** — no telemetry, no remote APIs, no CDN assets at runtime. One exception: optional packs (the Office pack, LibreOffice; the AI pack, ONNX Runtime + BiRefNet lite + Real-ESRGAN) are downloaded only after the user explicitly agrees, by the `packs` crate; conversions never touch the network.

## Repository layout

```
Cargo.toml          # workspace root
crates/engine/      # pure Rust: all conversion logic + tests. NO Tauri deps.
crates/placement/   # pure window-placement math (multi-monitor / DPI), no deps
crates/packs/       # optional downloads (Office pack, AI pack): pinned builds, consent-gated download, verify, unpack
src-tauri/          # thin shell: commands, tray, hotkeys, windows
src/                # React frontend
  api.ts            # the only place the frontend talks to Rust
```

Plus `index.html`, `vite.config.ts` (port 5000, `strictPort`), and `src-tauri/tauri.conf.json` (`devUrl` = `http://localhost:5000`).

## Architecture rules

1. **Cargo workspace** with four members:
   - `crates/engine` — all conversion logic and its tests. Must never depend on `tauri` or any UI crate, so it builds and tests on Replit.
   - `crates/placement` — pure arithmetic for positioning the radial window (multi-monitor, mixed DPI). Split out of the shell only so it is testable on Replit.
   - `crates/packs` — the only code that may use the network: downloads a pinned pack after consent, verifies its SHA-256, unpacks it into the app data dir. No Tauri deps; tested against a local HTTP server.
   - `src-tauri` — thin shell only: Tauri commands, tray, global hotkeys, window management. No conversion logic here; commands just delegate to the engine.
2. **Engine trait** (each converter implements it):
   ```rust
   fn can_handle(&self, mime: &str) -> bool;
   fn operations(&self, mime: &str) -> Vec<Operation>;
   fn run(&self, op: &Operation, inputs: &[PathBuf], options: &Options) -> Result<Vec<PathBuf>>;
   // optional, default empty: ops for a whole selection (e.g. Merge PDFs)
   fn batch_operations(&self, mimes: &[String]) -> Vec<Operation>;
   // optional: the engine's name for the log ("LibreOffice", "pandoc", "AI"), default "built-in"
   fn name(&self) -> &'static str;
   // optional, default calls `run`: progress + cancellation through `Job` (long runs override it)
   fn run_job(&self, op: &Operation, inputs: &[PathBuf], options: &Options, job: &Job) -> Result<Vec<PathBuf>>;
   ```
   `run` returns the paths of the files it wrote. Output goes next to the original input; never overwrite an existing file (pick a unique name). Inputs may be of mixed types, so detect each file's format. Ops needing a missing external tool are still listed with `available: false`.
3. **Frontend ↔ Rust only through the typed `api.ts` wrapper.** Components never call `invoke` directly. When not running inside Tauri (`window.__TAURI_INTERNALS__` absent), `api.ts` uses mocks so the UI works in a plain browser.
4. Operation/option types are shared in shape between Rust (serde) and TypeScript; change both sides together.

## Development environment

- **Replit:** browser preview of the Vite frontend (mock mode) and `cargo test -p engine`. Do not try to build or run the Tauri shell there (no webview/GUI libs).
- **Local machine:** anything desktop-specific — tray, global hotkey, cursor-positioned window, drag-drop from the OS, `cargo tauri dev` — must be tested locally. State clearly when a change is only verifiable locally.

## Commands

- Frontend dev (browser preview, mock mode): `npm run dev` (port 5000)
- Frontend typecheck + bundle: `npm run build`
- Engine tests: `cargo test -p engine` (LibreOffice tests use `RUPANTAR_SOFFICE`, else `soffice`/`libreoffice` on PATH, and skip without one; AI inference tests use the AI pack at `RUPANTAR_AI_PACK` (a pack dir with `installed.json`), else the app's own (`~/.local/share/app.rupantar/packs/ai` on Linux), and skip without one)
- Pack tests: `cargo test -p packs` (local server, no network). The real pinned Linux builds: `RUPANTAR_LO_TARBALL=<downloaded .tar.gz> RUPANTAR_AI_DOWNLOADS=<dir with the AI pack's files, named as in the manifest> cargo test -p packs -- --ignored` (`RUPANTAR_AI_KEEP=<dir>` keeps the installed AI pack, e.g. for `RUPANTAR_AI_PACK`)
- Desktop dev (local only, needs webkit2gtk on Linux): `npm run tauri dev`. Run `scripts/fetch-sidecars.sh [target-triple]` first: `bundle.externalBin` makes Tauri refuse to build without `src-tauri/binaries/{pandoc,typst}-<triple>`. Also run `scripts/fetch-pdfium.sh [target-triple]`: `bundle.resources` needs `src-tauri/resources/pdfium/` (a Linux x64 `libpdfium.so` is committed; the script replaces it with the target's library).
- Refresh the frontend's mock operations after changing engine ops: `UPDATE_SNAPSHOT=1 cargo test -p engine`

## Conventions

- Engine: every converter has unit tests; use small fixtures under `crates/engine/tests/`. Errors via a typed error enum, no panics on bad input.
- Frontend: TypeScript strict; Tailwind for styling; Framer Motion for radial menu animation.
- Keep the shell thin; when tempted to add logic to `src-tauri`, put it in `engine`.
